# Claude tooling local permissions

This page documents the local Claude tooling permission allow-list that gates which commands the assistant may run inside this repository.

## When to use this page

- **Review** the allow-list before adding a new development tool or shell recipe exposed to Claude.
- **Audit** the permitted commands when extending automated build, test, or repository-inspection flows.
- **Diagnose** "permission denied" responses from Claude by comparing the requested command against the listed patterns.
- **Coordinate** with the team's command-wrapper conventions (for example, `rtk` aliases) when proposing new entries.

## How it fits

The file `.claude/settings.local.json` lives at the top level of the `.claude` directory and is the only artifact in this module. It ships a single `permissions.allow` array, which is the module's sole contribution: a local, repository-scoped policy that the Claude tooling consults before executing shell commands. The module does not define code, libraries, or runtime symbols; its role is configuration that authorises a narrow set of Bash invocations and nothing else.

## Allow-listed Bash patterns

The `permissions.allow` array enumerates seven string patterns. Each entry is a literal `Bash(...)` token, which Claude matches against the exact command line being requested.

```json
{
  "permissions": {
    "allow": [
      "Bash(rtk ls *)",
      "Bash(rtk git *)",
      "Bash(pnpm -r build)",
      "Bash(pnpm -r test)",
      "Bash(rtk grep *)",
      "Bash(rtk find *)",
      "Bash(rtk wc *)"
    ]
  }
}
```

The visible entries fall into two families. Repository inspection commands go through the `rtk` wrapper — `rtk ls`, `rtk grep`, `rtk find`, `rtk wc`, and `rtk git` — each suffixed with a glob so any arguments are accepted. Build and test execution goes directly through `pnpm -r build` and `pnpm -r test`, which target the full workspace recursively. No deny list, default-deny fallback, or other top-level keys are visible in the supplied source, so any Bash invocation outside these seven patterns is outside the documented scope of this file.
